## Come si lavora

- La radice del repo è la cartella che dà `git rev-parse --show-toplevel` (qui `coletta-preventivi/`): i comandi (`npm …`, `npx …`, `git …`) si lanciano da lì.
- Claude Code si avvia **da `coletta-preventivi/`**, non dalla cartella sopra: da lì le rule di
  `.claude/rules/` non si caricano, e niente lo segnala (misurato il 07/10/2026: dalla cartella
  sopra nessuna rule in nessuna delle letture di prova; da `coletta-preventivi/` tutte).
- Le rule di area (`.claude/rules/<area>.md`) si caricano quando un file della loro area viene
  aperto col tool Read, non con `cat`/`sed` da Bash; `qualita.md` è senza `paths:` ed è sempre in
  contesto. Elenco delle aree e dei loro glob: il frontmatter di ogni rule, fino al secondo `---` e non per un numero fisso di righe: `awk 'FNR==1{n=($0=="---")?0:2} n<2{print FILENAME": "$0} /^---$/{n++}' .claude/rules/*.md`.

## Architettura

### Flusso dei dati

Bucket Supabase `Listini` → file Excel → Web Worker (`XLSX.read`) → parser → validazione Zod →
`pricelistStore` → engine di calcolo → componenti e stampa PDF.

- Il bucket si chiama `LISTINI_BUCKET` (`src/lib/supabase.ts:35`); il client è `createClient` (`src/lib/supabase.ts:41`).
- `loadDefaults` (`src/store/pricelistStore.ts:523`) lista il bucket ordinando per `updated_at` (`src/store/pricelistStore.ts:545`), assegna la categoria col nome del file via `categorizzaListino` (`src/store/pricelistStore.ts:155`), che controlla porte → marmeria → cucine → su misura, e prende il più recente per ognuna delle quattro categorie. Un listino assente si notifica, cucine compreso.
- Il parsing gira nel worker: `parseExcelInWorker` (`src/lib/excelWorker.ts:34`) prima confronta `dimensioneDecompressa` (`src/lib/dimensioneZip.ts:32`), che sul main thread legge solo la central directory dello zip, col tetto `MAX_DECOMPRESSO_BYTE` (`src/lib/dimensioneZip.ts:7`), poi crea il `new Worker` (`src/lib/excelWorker.ts:78`) con il timeout `TIMEOUT_PARSE_MS` (`src/lib/excelWorker.ts:15`); il worker chiama `XLSX.read` (`src/workers/excelParser.worker.ts:49`). L'anagrafica da importare (L21-C) passa dallo stesso worker, ma prima di `XLSX.read`: `leggiCsvAnagrafica` (`src/lib/anagraficaCsv.ts`).
- Parser per listino: `parseSuMisura` (`src/parsers/parseSuMisura.ts:253`), `parseMarmeria` (`src/parsers/parseMarmeria.ts:420`), `parsePorte` (`src/parsers/parsePorte.ts:220`), `parseCucina` (`src/parsers/parseCucina.ts:129`), che legge il foglio CUCINA: riceve la sola struttura senza prezzi e abbina i nomi.
- Validazione dopo il parsing, sul main thread: `validaListinoMarmeria` (`src/parsers/marmeriaSchema.ts:127`), `validaListinoPorte` (`src/parsers/porteSchema.ts:73`), `validaListinoCucina` (`src/parsers/cucinaSchema.ts:50`).
- `AppShell` chiama `loadDefaults` (`src/components/layout/AppShell.tsx:62`) al montaggio, quando la sessione Supabase esiste già.

### Avvio e autenticazione
